# MC 模组美术方案调研

日期：2026-10-08。状态：方案调研；尚未安装工具或验证模型制作效果。

## 目标

用户不亲自建模，参与造型方向与成品效果的评审。
交付模型应可编辑、带贴图和可用动画，并能接入所选模组版本。
模型生成成功、格式可导出、美术质量合格、游戏中能正常运行，分别验证。

## 路线 A：概念与基础资产 + Blockbench 自动化

Blockbench 支持 Minecraft 实体与 GeckoLib 等专用模型格式。
先用原著形态描述、概念参考和适用的基础资产确定轮廓，再用自动化生成与修改方块模型。
需要区分参考资产与可直接使用的资产，逐件检查使用与改编许可。

开源项目 jasonjgardner/blockbench-mcp-plugin 提供两种方式：

- 桌面插件：通过 MCP 操作正在运行的 Blockbench。
- Headless 服务：直接创建、编辑、验证与渲染 .bbmodel 文件，无需运行编辑器；适合分文件制作。

Headless 文档列出模型、UV、贴图、骨架组和关键帧编辑，以及多视角渲染、模型与动画检查。
导出能力按格式确认；GeckoLib 成品导出需要进一步验证桌面插件与所需版本的完整流程。
动画检查存在采样与表达式限制，仍需实际预览与游戏内检查。
渲染工具有 Node 与 GPU 要求，接入前需检查本地环境。

工具接入可以提高编辑与检查效率，不能单独保证模型的审美质量。

## 路线 B：通用 AI 三维生成

Meshy 等服务可以从描述或图像生成网格、贴图，并对支持的结构提供自动绑定。
Meshy 官方 Minecraft 页面明确说明不导出 .bbmodel 或 Java 原生模型文件；其 MC 风格网格不能直接作为原版实体模型使用。
我们的方块实体与 GeckoLib 候选流程需要进一步重建或转换；通用网格也可通过额外自定义渲染集成，但开发与维护成本需另评估。
九尾、多首、独足等特殊结构的骨架与动作不能依据普通自动绑定宣传推定可用。
适合辅助概念、轮廓与静态参考，直接交付实体资产的可行性应以样件验证。
具体价格、额度、许可与账户状态在实际使用前核对。

## 路线 C：现成资产或委托制作

普通动物与通用动作可评估合适的现成资产；特殊神话结构可考虑委托专门的 Blockbench 美术。
预算允许时，可以把少数标志性异兽交给专业制作，通用内容采用自动化与基础资产。
交付约定应含源文件、贴图、骨架、动画、游戏版本与使用许可。
这一方式也不要求用户亲自建模，但有采购、沟通和改版成本。

## 建议先做制作流程的样件

推荐候选：参考与基础资产 → Blockbench 自动化 → 对应版本的 GeckoLib → 游戏内验证。
用一个常规体型与一个特殊结构分别验证，避免只用简单方块证明流程。
先做造型与动作样件，通过后再批量制作。

每个样件交付：

- 可编辑 .bbmodel 源文件。
- 模型、贴图与动画导出文件；具体格式依加载器与动画库确定。
- 正面、侧面、背面及透视预览。
- 待机、移动、警戒和代表性动作预览。
- 游戏尺度、贴图接缝、骨骼与动画、导出与资源加载的验证记录。

美术评审关注轮廓、比例、特征辨识、色块分布、纹理一致性与动作表现。
自动检查关注骨架与资源完整性、明显穿插、动画离地和格式约束，不能替代美术评审。
若样件质量不合格，应改变参考、资产或制作路线，而不直接扩大数量。
